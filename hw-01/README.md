# Домашняя работа 1

Каталог содержит стенд для демонстрации продукта: три веб-сервера в двух зонах за сетевым балансировщиком и отдельный сервер приложения без публичного адреса. Выход закрытого сервера в интернет обеспечивается NAT-шлюзом.

## Требования

- bash, git, Yandex Cloud CLI, jq, curl, ssh и envsubst;
- настроенный профиль `yc`;
- открытый SSH-ключ `~/.ssh/id_ed25519.pub`.

Запускать команды нужно из корня репозитория.

## Создание

```bash
time bash hw-01/create.sh
```

Повторный запуск не создаёт дубликаты. Аргумент командной строки важнее переменной окружения, переменная окружения важнее значения варианта.

Пример изменения числа веб-серверов:

```bash
./hw-01/create.sh --web-count 3
```

Поддерживаются параметры `--prefix`, `--zone-a`, `--zone-b`, `--cidr-a`, `--cidr-b`, `--app-port`, `--greeting`, `--web-count` и `--env-name`.

Значения варианта по умолчанию: префикс `safronov-08`, зоны `ru-central1-b` и `ru-central1-d`, подсети `10.18.1.0/24` и `10.18.2.0/24`, порт `8024`, слово `labwork`, три веб-сервера, окружение `stage`.

## Проверка

```bash
bash hw-01/check.sh
echo $?
```

Код `0` означает, что балансировщик отвечает кодом 200, ответы приходят больше чем с одной машины и сервер приложения доступен с первого веб-сервера. Код `1` означает, что хотя бы одна проверка не прошла. В этом случае нужно посмотреть строки со знаком `✗`, проверить состояние ВМ и nginx, а затем повторить запуск.

## Удаление

```bash
bash hw-01/destroy.sh
```

После удаления следует проверить списки виртуальных машин, дисков, адресов, сетей и балансировщиков. В списке сетей останется стандартная сеть `default`.
